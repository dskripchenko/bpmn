# Начало работы

```sh
npm install @dskripchenko/bpmn
```

## Отрисовка файла

```ts
import { render } from '@dskripchenko/bpmn'

const { svg, width, height, warnings } = render(xml)
container.innerHTML = svg
```

`render` принимает текст файла `.bpmn` и возвращает:

| Поле       | Что это                                                                 |
| ---------- | ----------------------------------------------------------------------- |
| `svg`      | Рисунок — готовый элемент `<svg>` текстом                               |
| `width`    | Ширина в пикселях                                                       |
| `height`   | Высота в пикселях                                                       |
| `diagram`  | id нарисованной диаграммы                                               |
| `warnings` | Что пропущено: фигуры элементов, которых нет в файле, потоки без точек  |

Рисунок повторяет раскладку, сохранённую в файле (раздел `BPMNDiagram`), —
её сохраняет любой моделер. Ничего не сдвигается. Файл без раскладки
отклоняется с объяснением.

## Параметры

```ts
render(xml, {
  diagram: 'Diagram_2', // или номер; по умолчанию первая диаграмма
  title: 'Обработка заказа', // доступный заголовок; по умолчанию имя диаграммы
  idPrefix: 'order', // id внутри SVG; уникальный, если файл показан на странице дважды
  padding: 10, // поле вокруг рисунка
  measureText, // как измерять текст; в браузере по умолчанию canvas
  limits: { maxLength: 1_000_000 }, // более строгие пределы для чужих файлов
})
```

## Ошибки

Файл, который нельзя прочитать, вызывает `BpmnError` со строкой и столбцом
ошибки и, если есть, подсказкой:

```ts
import { BpmnError, render } from '@dskripchenko/bpmn'

try {
  render(xml)
} catch (e) {
  if (e instanceof BpmnError) console.log(e.message, e.line, e.column, e.hint)
}
```

## Чтение модели

`parse` возвращает семантику и раскладку без отрисовки:

```ts
import { parse } from '@dskripchenko/bpmn'

const model = parse(xml)
model.elements.get('Task_Check') // { id, type: 'userTask', name, parent, eventDefinitions, loop, xml }
model.diagrams[0].shapes // [{ element, bounds, label, isExpanded, colors }, …]
```

Каждый элемент хранит свой XML-узел (`xml`) со всеми атрибутами и дочерними
элементами любых пространств имён, включая расширения поставщиков.
`writeXml(model.document)` записывает файл обратно.

Вместо текста в `render` можно передать модель — чтобы нарисовать несколько
диаграмм одного файла, не читая его заново.

## В браузере и на сервере

`render` не нужен DOM. На сервере текст измеряется по таблице ширин знаков,
в браузере — через canvas, поэтому подписи переносятся под шрифты читателя.
Чтобы вывод везде совпадал, передайте `approximateMeasurer`:

```ts
import { approximateMeasurer, render } from '@dskripchenko/bpmn'
render(xml, { measureText: approximateMeasurer })
```

## Что рисуется

События всех видов и определений, задачи всех типов, вызовы процессов,
подпроцессы (свёрнутые, развёрнутые, событийные, транзакции, ad hoc), маркеры
цикла, множественного экземпляра и компенсации, шлюзы, объекты и хранилища
данных, текстовые аннотации, группы, пулы и дорожки, все виды потоков и
диалоги (conversation). Хореографии рисуются простыми блоками с именами.

Каждый элемент — это `<g class="bpmn-element bpmn-type-userTask" data-element-id="Task_Check">`,
поэтому страница может найти его, подсветить или повесить обработчик.
